    Advanced

    Each lamp gets the band count that fits its width (about one band per column; “Spectrum bands” is then ignored) and can have its own mode and start point on its card. Off: every lamp gets the same stream and settings.

    On / Off and brightness apply to every connected lamp and are saved on the lamp, like its own controls. Older firmware without the control capability gets them over HTTP (/api/power, /api/brightness) and its state is not shown.

    Only DSP features are sent, never audio. Lamp endpoint: ws://address/audio. A page served over HTTPS may block ws://; open it from localhost or as a file. “+” delays the light, “−” advances it.

    These values are sent to the lamp with the audio and apply only while streaming; the preset saved on the lamp is not changed.

    Preview only: the lamp draws the line from the signal source.

    Visualization

    Reaction range

    The signal window “from–to” is stretched onto the reaction “from–to”. Above “to” the reaction is always at maximum; below “from” it stays at the minimum, or 0. Example: signal 0–60% → reaction 150–250.

    Curve bends the stretch: LED brightness looks logarithmic (50% → 100% barely changes), so a curve of ×2–×2.5 keeps quiet and mid signals dim and makes the reaction look even. Below linear it lifts quiet signals.

    How it works

    Spectrum and Wave do not draw on top of the picture; they scale the brightness of the running effect per column. Speed / Scale / Light Control change the preset parameter before rendering, as in the firmware. The preview uses the same DSP whose features the lamp receives. Everything on this tab except “Fast line response” and “LED reaction” is sent to the lamp.

    ×

    Orientation and accuracy

    Orientation test: red (0,0), green (W−1,0), blue (0,H−1), white (W−1,H−1) in firmware coordinates. Flipping only changes the display. Addressing is serpentine, like Led::get_index; long strips wrap onto several display lines.

    Effects are hand-ported to C++/WASM; an exact match with the firmware is not proven (FastLED version, frame timing, physical LEDs). LED output simulation is approximate: brightness and TypicalLEDStrip correction, without current limiting or dithering.

    Audio analyzer settings. They affect both the preview and what the lamp receives.

    Bands are spread logarithmically inside this range; sound outside it is ignored. Example: 200 Hz – 4 kHz for vocals and leads, 40–250 Hz for bass only.

    Details

    Hann-windowed FFT at 16 kHz (so the top frequency is 8 kHz), 16 logarithmic bands for the classic preview modes (16/32/64 for the lamp and the lab-preview modes), envelope attack/release, adaptive noise floor, spectral-flux onset detector and an experimental tempo estimate (may be wrong on complex music).

    Everything is processed locally in the browser · only audio features are sent to the lamp
